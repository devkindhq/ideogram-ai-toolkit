# Reading a brand.md Visual layer

`brand.md` (the format generated by the `brand-md` skill) has a Visual layer with three sections. Each maps onto prompt language differently — the mistake is treating them as an equal-weight list of facts to recite, instead of extracting the *usage rule* buried in each one.

## Colors

A brand.md Colors section names Primary / Secondary / Accent with hex values *and* a usage rule per color — that usage rule is the load-bearing part, not the hex itself.

Example from a fictional voice-dispatch brand's brand.md ("Fleetline"):
- Primary — Radio Amber `#C1571F`: "the mark's dominant colour or accent stroke"
- Secondary — Slate Ink `#262019`: "wordmark colour on light backgrounds, or the base the amber sits on in reverse"
- Accent — Signal Green `#4F7A46`: "reserved for a 'resolved/answered' state variant of the mark only... not part of the primary lockup"

**What this means for a prompt:** don't just list three hex codes and let the model decide how to use them. Say which one dominates, which one is the ground/base, and which one is *excluded from the default mark entirely* (only appears in a variant). A model given three co-equal colors will often blend them or use them decoratively; a model told "amber dominant, ink is the base it sits on, sage never appears in the primary lockup" produces a mark with actual hierarchy.

Also carry over the **Avoid** line if the brand.md has one — e.g. "avoid corporate signal-blue, avoid purple-to-pink gradients" — these go straight into the prompt's negative-space section.

## Typography

brand.md separates Display / Body / Mono, each with a named reference face and a usage note. For a logo prompt you almost always want the **Display** face's description (not body or mono, unless the brand's whole identity concept is that the mono face IS the logo — see the "Paper Trail" direction in `examples/fleetline-four-directions.md` for that exception).

Translate "Inter Tight or Söhne, medium/semibold, roman only, no italics" into prompt language as a *genre description* the image model can act on: "a grounded medium-weight grotesk sans-serif, roman, no italics" — naming the exact commercial typeface in a generation prompt is close to useless (image models don't reliably render specific licensed fonts), but naming the *genre and weight* reliably steers the output.

## Style

The Style section's "Design keywords" and "Reference brands" lines are where the mood-anchor sentence in a prompt comes from. Don't just paste the keyword list ("dispatch, grounded, unhurried, legible-first, quietly-technical") as-is into a prompt — that's adjective soup again. Pick the one or two reference brands or reference *objects* named in the Direction statement and use those as the concrete anchor instead ("should look like infrastructure a shift worker trusts, not a demo-day pitch deck slide" → "a well-machined analog radio dial," not "trustworthy and modern").

## When there's no brand.md yet

If the project has no brand.md, don't invent Visual-layer facts. Either:
- Generate one first (invoke the `brand-md` skill), or
- Ask the four visual questions directly: primary/secondary/accent color with a role for each, display typeface genre, 2-3 style keywords anchored to a real reference brand or object, and what the mark must never look like.
